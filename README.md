# kino-cli

Отвечает на один вопрос: **какие три фильма, вышедшие в цифре за последнюю неделю, стоит посмотреть сегодня вечером.**

Оценки агрегируются из независимых публичных источников — IMDb, TMDB, Кинопоиск,
OMDb. Рейтинг и редакционные подборки Кинопоиска не определяют общую выдачу:
там правит зрительская масса IMDb и TMDB. Российское кино участвует на равных, а
там, где его массовая аудитория реально живёт — на Кинопоиске, — для него есть
отдельная дорожка `kino ru`.

```
$ kino ru 180
TOP 3 — новые русскоязычные фильмы
1 марта — 28 августа
ранжировано по оценкам Кинопоиска · часть фильмов пока только в прокате

1. К себе нежно                               7.3
   IMDb 5.3 / 80 · КП 7.3 / 299K
   🇷🇺 Россия · комедия · 109 мин
   Релиз: 5 марта
   ▶ Есть на Кинопоиске
```

## Установка

```bash
go build -o ~/.local/bin/kino ./cmd/kino
```

`~/.local/bin` уже в `PATH`, sudo не нужен. Проверка: `kino --help`.

Ключи — в `~/.config/kino/config.toml` или в переменных окружения (`chmod 600`):

| Переменная | Обязательна | Откуда |
|---|---|---|
| `TMDB_TOKEN` | да | themoviedb.org/settings/api → API Read Access Token (v4) |
| `KINOPOISK_API_KEY` | нет, но нужен для `ru` | telegram-бот `@kinopoiskdev_bot`, 200 запросов/сутки |
| `OMDB_API_KEY` | нет | omdbapi.com/apikey.aspx, 1000 запросов/сутки |

`kino config check` покажет, какие ключи видны, размер БД и остаток квот.

### Первый запуск

```bash
kino setup
```

Пять вопросов о том, что вы смотрите, затем ключи, затем наполнение базы. Ответы
превращаются в коэффициенты ранжирования — читать TOML до первой рекомендации не
нужно.

| Вопрос | Что двигает |
|---|---|
| громкое / поровну / редкое | вес уверенности, пороги допуска, штраф за артхаус, байесовское сглаживание |
| смотрят ли дети | штрафы за семейное и анимацию; отдельный ответ для взрослого аниме |
| сверять ли Кинопоиск с миром | штраф за расхождение в дорожке `kino ru` |
| важна ли свежесть | вес свежести и окно по умолчанию |
| сколько фильмов показывать | размер списка |

Мастер не перезаписывает существующий `config.toml` без `--force` — файл хранит
ключи, и молча заменить его значило бы их потерять. Для скриптов вместо опроса:
`kino config init`.

Вручную то же самое:

```bash
kino config init     # config.toml с дефолтами, ключи вписать в [secrets]
kino update imdb     # датасеты IMDb, ~50 секунд, 111 МБ через поток
kino sync            # свежие релизы, каталог КП, рейтинги
```

## Рекомендации

Главная команда — без аргументов:

```bash
kino                 # 3 фильма, вышедших в цифре за 7 дней
kino 30              # окно 30 дней
kino ru              # русскоязычное, ранжировано по Кинопоиску (окно 30 дней)
kino ru 180          # русскоязычное за полгода
kino триллер 60      # только триллеры за 60 дней
kino ru комедия 90
```

Жанр пишется по-русски или по-английски: `драма`, `комедия`, `триллер`, `ужасы`,
`фантастика`, `детектив`, `боевик`, `криминал`, `мелодрама`, `мультфильм`,
`документальный`, `семейный`, `приключения`, `фэнтези`, `история`, `музыка`,
`военный`, `вестерн`.

| Флаг | Что делает |
|---|---|
| `--all` | не 3 фильма, а все прошедшие отбор |
| `--why` | разложить оценку по слагаемым: рейтинги, уверенность, массовость, свежесть, штрафы |
| `--seen` | не прятать уже просмотренное |
| `--reissues` | вернуть переиздания: старые фильмы, только что доехавшие до стриминга |

### Две дорожки

Они отвечают на разные вопросы и потому считаются по-разному.

|  | общая (`kino`) | русская (`kino ru`) |
|---|---|---|
| источники оценки | IMDb + TMDB | Кинопоиск + IMDb/TMDB как контроль |
| дата | подтверждённый **цифровой** релиз (TMDB release type 4) | дата релиза; фильм может быть ещё только в прокате |
| порог | 300 голосов IMDb или 100 TMDB | 3000 голосов Кинопоиска |

Причина разделения: TMDB для большинства российских и казахстанских фильмов
вообще не содержит записи о цифровом релизе. Требовать её — значит вычеркнуть
это кино целиком. Из 81 фильма, доступного на Кинопоиске, у 48 не было
type-4 релиза в TMDB.

### Бейджи

| | Значение |
|---|---|
| `🔥 Хорошо принят зрителями` | высокая оценка при большом числе голосов |
| `🔥 Зрителям нравится значительно больше, чем критикам` | разрыв аудитория/критики в пользу зрителей |
| `⚠ Критики оценили заметно выше зрителей` | обратный разрыв — типичный признак фестивального кино |
| `⚠ Международная аудитория оценила заметно ниже` | Кинопоиск сильно выше IMDb (только в русской дорожке) |
| `🎨 Риск артхауса` | жанр + мало голосов + высокая оценка |
| `👶 Детское / семейное`, `👶 Анимация` | штрафуется, чтобы не вытеснять взрослое кино |
| `▶ Есть на Кинопоиске` | подтверждённая онлайн-доступность |
| `🎬 Только в прокате` | доступность проверена и её нет |

Последний бейдж ставится, **только если кто-то нам это сказал**. Отсутствие
данных — не то же самое, что отсутствие фильма онлайн: колонка `watch_online`
трёхзначная (1 / 0 / NULL).

## Просмотренное

```bash
kino watched Коммерсант 8      # отметить, оценка необязательна
kino watched --list
kino watched --forget Коммерсант
```

Отмеченное исчезает из рекомендаций, пока не позовёшь с `--seen`.

## Настройка модели

Все коэффициенты вынесены в TOML — код не трогается:

```bash
kino setup --force   # пройти опрос заново, ключи сохранятся
kino config init     # записать ~/.config/kino/config.toml с текущими значениями
kino config show     # какие коэффициенты действуют сейчас
```

Файл можно резать: указываешь только то, что меняешь, остальное берётся из
дефолтов.

```toml
[weights]              # сумма обязана быть 1.0 ± 0.001
imdb = 0.45
tmdb = 0.25
confidence = 0.15      # много голосов → выше
mainstream = 0.10      # массовый жанр и популярность
freshness = 0.05

[thresholds]
min_imdb_votes = 300
min_kp_votes = 3000
min_runtime = 70            # отсекает короткий метр и концерты
max_release_gap_years = 2   # 0 — не отсекать переиздания

[bayes]                # сглаживание: (v/(v+m))·R + (m/(v+m))·C
imdb_m = 5000
kp_m = 5000            # для казахстанских фильмов 4000 голосов — уже много

[kids]
penalty = 1.0          # детское/семейное
animation_penalty = 0.5

[arthouse]
max_penalty = 1.0      # поставь 0, чтобы выключить

[gap_penalty]          # разрыв Кинопоиск ↔ IMDb в русской дорожке
max_penalty = 1.0
```

Приоритет: встроенные дефолты → `config.toml` → устаревший `config.env` →
переменные окружения.

## Автодополнение

```bash
kino completion zsh > "${fpath[1]}/_kino"      # zsh
kino completion bash | sudo tee /etc/bash_completion.d/kino   # bash
```

Дополняются не только команды и флаги, но и позиционная грамматика: `ru` и
названия жанров в обоих написаниях.

## Наполнение базы

```bash
kino sync                       # всё сразу, для крона
kino sync --window 14d --kp-years 3

kino update imdb                # датасеты IMDb (рейтинги + фильмы)
kino update kp --from-year 2025 --add-missing   # каталог Кинопоиска: id, рейтинги, где смотреть
kino update movies --last 7d    # TMDB discovery с ручными фильтрами

kino refresh ratings --limit 500   # рейтинги КП, без ключа и без квоты
kino import kp ~/kp.json           # выгрузка расширения или плеера
```

`kino sync` — пять шагов, каждый переживает падение остальных: упавший шаг
печатает ошибку, прогон продолжается, код возврата сообщает число неудач.
Подробности и крон — в [docs/memory-bank/60-operations.md](docs/memory-bank/60-operations.md).

### Быстро наполнить с нуля

Порядок важен: сначала бесплатное и объёмное, потом квотируемое.

```bash
kino update imdb                                   # 1.7 млн оценок, ~50 с, без ключа
kino update movies --last 1y --min-votes 50        # мировые релизы за год, TMDB без лимита
kino update movies --last 1y --original-language ru --release-type any
kino update kp --from-year 2024 --min-votes 10 --add-missing   # ~17 запросов из 200
kino refresh ratings --limit 2000                  # рейтинги КП, бесплатно
```

Полчаса, из них квоты тратит только четвёртая строка. На выходе — база, из
которой уже можно спрашивать рекомендации за любой период.

Ускорить нельзя: `update kp` упирается в потолок демо-тарифа (10 страниц по 250
фильмов за один фильтр), поэтому каталог обходится полосами по числу голосов.
Бюджет запросов ограничен `--max-pages` (по умолчанию 40).

### Забрать весь каталог Кинопоиска за несколько дней

Каталог больше суточной квоты: 1990–2026 — это около **183 000 фильмов, ~730
запросов** при 200 в сутки. Замеры по срезам:

| годы | страниц | ≈ фильмов |
|---|---|---|
| 2026 | 4 | 1 000 |
| 2024–2025 | 31 | 7 750 |
| 2020–2023 | 91 | 22 750 |
| 2010–2019 | 303 | 75 750 |
| 1990–2009 | 302 | 75 500 |

Забирается это скриптом, который берёт по куску в день и запоминает, где
остановился:

```bash
install -m 755 scripts/kino-backfill ~/.local/bin/kino-backfill
(crontab -l 2>/dev/null; echo "30 7 * * * $HOME/.local/bin/kino-backfill") | crontab -
```

**Время не то же самое, что у `kino-daily`** — иначе они подерутся за одну
квоту. Скрипт сам оставляет `KINO_BACKFILL_RESERVE` (по умолчанию 40) запросов
дневному обновлению и не выходит в сеть, если остатка не хватает.

Границы задаются переменными до первого запуска:

```bash
KINO_BACKFILL_FROM=1990 KINO_BACKFILL_TO=2026 KINO_BACKFILL_MIN_VOTES=10 kino-backfill
```

Дальше состояние в `~/.local/share/kino/backfill.state` ведёт себя как источник
истины: `cursor=<голоса>` — где продолжить, `done=1` — каталог пройден, скрипт
молча выходит и квоту больше не тратит. Лог — `backfill.log`.

Вручную то же самое: прогон печатает точку продолжения, когда упирается в
бюджет.

```bash
kino update kp --from-year 2020 --to-year 2023 --min-votes 10 --max-pages 150 --add-missing
# фильмов 2750: ...
# бюджет исчерпан; продолжить: --max-votes 4202
```

Назавтра — та же команда с `--max-votes 4202`. Выдача отсортирована по числу
голосов убыванию, поэтому опущенный потолок продолжает обход ровно с места
остановки, а не сверху.

Прогон с `--add-missing` идёт **десятки минут**: каждый неопознанный фильм
ищется в TMDB. Это работа для крона, а не для интерактивной проверки.

### Держать свежей

```bash
(crontab -l 2>/dev/null; echo "0 6 * * * $HOME/.local/bin/kino-daily") | crontab -
```

`kino-daily` — обёртка вокруг `kino sync`: задаёт `PATH` (у крона он урезан),
пишет `~/.local/share/kino/sync.log` с отметкой времени и кодом возврата,
подрезает лог до 2000 строк. Один прогон стоит около двадцати запросов из
двухсот суточных.

Проверить, как отработало: `tail -30 ~/.local/share/kino/sync.log`.

Рейтинги обновляются не всё подряд: **период зависит от возраста фильма**.
Оценка движется быстрее всего сразу после релиза, когда несколько тысяч новых
голосов сдвигают её на десятые, и почти не движется годы спустя, когда те же
голоса ложатся на базу в сотни тысяч.

| возраст фильма | как часто перечитывается |
|---|---|
| до 30 дней | раз в сутки (базовый `--stale-hours`) |
| до 90 дней | ×3 |
| до года | ×14 |
| старше | ×60 |

На нашей базе это сократило очередь с 4063 фильмов до 220: дневной бюджет
уходит туда, где рейтинг действительно меняется, а не на перечитывание чисел,
которые не сдвинулись. Внутри прогона свежие идут первыми.

Переносить базу между машинами — только через снимок, а не копированием файла:

```bash
sqlite3 ~/.local/share/kino/kino.db "VACUUM INTO '/tmp/kino-snapshot.db'"
```

База в режиме WAL: свежие транзакции живут в `kino.db-wal` рядом, и простое
копирование даст состояние без них — а если в этот момент сработает крон, снимок
будет разорван. При замене базы на месте удаляйте `-wal` и `-shm` вместе с ней:
журнал от старой базы будет применён к новой при открытии.

## Произвольные запросы к базе

Рекомендатор отвечает на один вопрос; для всего остального есть `list` —
работает по локальной БД, без сети.

```bash
kino list --since 7d --min-rating 7 --sort rating
kino list --since 1m --original-language ru --release-type any
kino list --since 30d --rating-source imdb --min-rating 7 --format json
kino show tt1285016
```

Пресеты: `kino new`, `kino ru-list`, `kino kz`, `kino kp`, `kino digital`,
`kino hot` / `rising` / `live` (тренды). Общие флаги: `--format table|json|csv`,
`--db <путь>`, `-v`.

## Источники

| Источник | Лимит | Что даёт |
|---|---|---|
| IMDb Non-Commercial Datasets | нет | 1.7 млн рейтингов, 229 тыс. фильмов; `title.basics` (200 МБ) читается потоком и фильтруется на лету — на диск не ложится |
| TMDB | нет | discovery, даты релизов по типам и регионам, жанры |
| poiskkino.dev | 200/сутки | каталог по фильтрам: 250 фильмов за один запрос, `watchability` со списком сервисов |
| rating.kinopoisk.ru | нет | точные рейтинги (5.311 против округлённого 5.4 у API) |
| OMDb | 1000/сутки | Metascore, Rotten Tomatoes |

Тренды с публичных чартов kinozal.me (`kino trends`) читают только метаданные —
названия, ранги, сиды, счётчик «Скачали». Торренты не скачиваются. К
рекомендациям тренды отношения не имеют и в `sync` по умолчанию не входят
(`--with-trends`).

## Расширение для браузера

`extension/` — Chrome MV3 для ручных подборок: листаешь выдачу Кинопоиска,
расширение собирает карточки в JSON для `kino import kp`.

**Сетевых разрешений у него нет вообще** — `permissions: ["storage"]`. Оно
физически не может ничего никуда отправить.

С появлением `kino update kp` расширение перестало быть основным путём: каталог
отдаёт то же самое дешевле и полнее. Осталось для случаев, которые фильтрами API
не выражаются.

**Лицензия распространяется на код, а не на данные.** Источники живут по своим
правилам, и они разные:

- **IMDb Non-Commercial Datasets** — только для личного и некоммерческого
  использования. Коммерческий продукт на этих данных строить нельзя, нужен
  отдельный договор с IMDb.
- **TMDB** — требует указания, что продукт использует их API и ими не
  сертифицирован; проверьте актуальные условия.

То есть код свободен, а собранная им база — настолько, насколько позволяют
источники. Для домашнего употребления это ничего не меняет; для продукта
условия каждого источника нужно прочитать самому.
