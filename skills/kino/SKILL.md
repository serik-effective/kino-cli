# kino

CLI-рекомендатор поверх локальной SQLite. Отвечает мгновенно и без сети: база
наполняется кроном отдельно.

## Проверка перед первым использованием

```bash
command -v kino >/dev/null && kino config check
```

Если команды нет или база пуста — скажи об этом и остановись. Не пытайся ставить
или настраивать: `kino setup` спрашивает ключи API и должен запускаться
человеком.

## Основное

Всегда добавляй `--format json` — разбирай структуру, а не карточки.

```bash
kino --format json                # 3 фильма за последние 7 дней
kino 30 --format json             # окно 30 дней
kino ru 180 --format json         # русскоязычное за полгода
kino комедия 60 --format json     # жанр за 60 дней
kino ru драма 90 --format json    # комбинируется
kino 90 --all --format json       # все прошедшие отбор, не только TOP-3
kino 90 --reissues --format json  # вместе с переизданиями старых фильмов
```

Число — дни, `ru` — дорожка русскоязычного кино, слово — жанр. Порядок любой.

Жанры: `комедия`, `драма`, `триллер`, `ужасы`, `фантастика`, `боевик`,
`криминал`, `детектив`, `мелодрама`, `мультфильм`, `документальный`, `семейный`,
`приключения`, `фэнтези`, `история`, `музыка`, `военный`, `вестерн`. Английские
названия тоже работают.

Просмотренное скрыто из выдачи. Отметить и снять:

```bash
kino watched "Название" 8
kino watched --list
kino watched --forget "Название"
```

## Как читать ответ

Полное описание формата — `docs/AGENTS.md` в репозитории. Четыре правила, на
которых ошибаются чаще всего:

1. **`"rating": null` значит «никто не голосовал», а не ноль.** Не говори, что
   фильм плохо приняли, если оценки просто нет.
2. **`availability.online_ru: null` значит «не проверяли».** Не утверждай, что
   фильм недоступен: `false` и `null` — разные ответы.
3. **`why.points` объясняют оценку** — четыре слагаемых минус три штрафа. Если
   спрашивают «почему этот фильм», отвечай ими, а не пересказом рейтингов.
4. **Переиздания по умолчанию отсеяны.** Старый фильм, доехавший до нового
   сервиса, — не новинка, и в выдаче его нет. Если просят ремастеры,
   переиздания или «что из классики появилось онлайн» — добавь `--reissues`.
5. **Не пересортировывай.** `score` уже учитывает объём выборки, массовость и
   свежесть. Сортировка по сырому рейтингу IMDb поднимет фильмы с десятком
   голосов.

## Две дорожки

Общая (`kino`) ранжирует по IMDb и TMDB и требует подтверждённого цифрового
релиза. Русская (`kino ru`) ранжирует по Кинопоиску и цифрового релиза не
требует: у большинства российских фильмов TMDB его просто не записывает.

Поэтому за русским кино ходи в `kino ru`, а не фильтруй общую выдачу по стране —
там его почти не будет. В русской дорожке поле `notice` предупреждает, что часть
фильмов пока только в прокате; это стоит передать пользователю.

## Пустой ответ

`films: []` — нормальный ответ, а не сбой: за неделю может не выйти ничего
достойного. Предложи более широкое окно (`kino 30`, `kino 90`), но не выдумывай
фильмы и не подставляй их из своих знаний — пользователь ждёт ответа про то, что
реально вышло и доступно.

## Наполнение и обновление базы

Всё здесь — сетевые операции с суточной квотой. Выполняй **только по явной
просьбе человека**. Пустой список фильмов не повод обновлять базу: это повод
предложить окно шире.

Проверить состояние:

```bash
kino config check                       # база, ключи, остаток квот
tail -3 ~/.local/share/kino/sync.log    # когда обновлялось
crontab -l | grep kino                  # настроено ли расписание
```

`rows in movies` равно нулю — база пустая. Лога нет или он старше суток —
обновление не идёт. Нет строки в `crontab` — расписание не настроено. Сообщи,
что нашёл, и предложи то, что ниже. Молча не выполняй.

**Первичное наполнение** пустой базы, около получаса, квоту тратит только
четвёртая строка:

```bash
kino update imdb
kino update movies --last 1y --min-votes 50
kino update movies --last 1y --original-language ru --release-type any
kino update kp --from-year 2024 --min-votes 10 --add-missing
kino refresh ratings --limit 2000
```

Если у человека есть готовая база на другой машине — перенести её снимком
дешевле: минуты вместо получаса и ноль запросов. Порядок в README проекта.

**Ежедневное обновление:**

```bash
install -m 755 ~/incoming/kino/kino-daily ~/.local/bin/kino-daily
(crontab -l 2>/dev/null | grep -v kino-daily; \
 echo "0 6 * * * $HOME/.local/bin/kino-daily") | crontab -
```

`grep -v kino-daily` обязателен: без него повторный запуск добавит вторую
строку и обновление пойдёт в сеть дважды.

Проверить — **ровно один раз**, не в цикле: `kino-daily; tail -12
~/.local/share/kino/sync.log`, ожидается `exit=0`. Прогон стоит около двадцати
запросов из двухсот суточных.

**Весь каталог Кинопоиска** (около 183 000 фильмов, ~730 запросов) одним
прогоном не берётся. Для этого есть `scripts/kino-backfill` — берёт по куску в
день, помнит место остановки, оставляет запас дневному обновлению. Ставится в
cron **на другое время**, чем `kino-daily`. Предлагай это человеку явно: добор
идёт несколько дней и всё это время держит квоту занятой.

**Рейтинги настраивать не нужно.** `kino sync` перечитывает их сам, и период
зависит от возраста фильма: до 30 дней — ежедневно, до 90 — втрое реже, до года
— в четырнадцать раз, дальше — в шестьдесят. Оценка свежего фильма движется
быстро, оценка старого практически стоит. «Рейтинг устарел» почти никогда не
повод что-то запускать руками.

Подробности — в `docs/AGENTS.md`. Разбор реальных ошибок при установке,
переносе и обновлении — в `docs/AGENT-PLAYBOOK.md`.

## Чего не делать

**Не запускай `kino sync`, `kino update` и `kino refresh` по своей
инициативе.** Это сетевые операции, они тратят суточные квоты (Кинопоиск — 200
запросов). По явной просьбе человека — можно, порядок выше. Сам, потому что
выдача показалась бедной, — нет.

**`kino setup` не запускай никогда:** он спрашивает ключи API и требует
терминал.

**Не советуй фильмы из своей памяти рядом с выдачей.** Смысл инструмента в том,
что рекомендация опирается на измеренные оценки и проверяемую доступность.
Смешивать их с припомненным — значит потерять единственное, ради чего он есть.
