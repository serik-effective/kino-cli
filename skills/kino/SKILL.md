# kino

CLI-рекомендатор поверх локальной SQLite. Отвечает мгновенно и без сети: база
наполняется кроном отдельно.

## Проверка перед первым использованием

```bash
command -v kino >/dev/null && kino config check
```

Если команды нет или база пуста — скажи об этом и остановись. Не пытайся ставить
или настраивать: `kino setup` спрашивает ключи API и должен запускаться
человеком.

## Основное

Всегда добавляй `--format json` — разбирай структуру, а не карточки.

```bash
kino --format json                # 3 фильма за последние 7 дней
kino 30 --format json             # окно 30 дней
kino ru 180 --format json         # русскоязычное за полгода
kino комедия 60 --format json     # жанр за 60 дней
kino ru драма 90 --format json    # комбинируется
kino 90 --all --format json       # все прошедшие отбор, не только TOP-3
```

Число — дни, `ru` — дорожка русскоязычного кино, слово — жанр. Порядок любой.

Жанры: `комедия`, `драма`, `триллер`, `ужасы`, `фантастика`, `боевик`,
`криминал`, `детектив`, `мелодрама`, `мультфильм`, `документальный`, `семейный`,
`приключения`, `фэнтези`, `история`, `музыка`, `военный`, `вестерн`. Английские
названия тоже работают.

Просмотренное скрыто из выдачи. Отметить и снять:

```bash
kino watched "Название" 8
kino watched --list
kino watched --forget "Название"
```

## Как читать ответ

Полное описание формата — `docs/AGENTS.md` в репозитории. Четыре правила, на
которых ошибаются чаще всего:

1. **`"rating": null` значит «никто не голосовал», а не ноль.** Не говори, что
   фильм плохо приняли, если оценки просто нет.
2. **`availability.online_ru: null` значит «не проверяли».** Не утверждай, что
   фильм недоступен: `false` и `null` — разные ответы.
3. **`why.points` объясняют оценку** — четыре слагаемых минус три штрафа. Если
   спрашивают «почему этот фильм», отвечай ими, а не пересказом рейтингов.
4. **Не пересортировывай.** `score` уже учитывает объём выборки, массовость и
   свежесть. Сортировка по сырому рейтингу IMDb поднимет фильмы с десятком
   голосов.

## Две дорожки

Общая (`kino`) ранжирует по IMDb и TMDB и требует подтверждённого цифрового
релиза. Русская (`kino ru`) ранжирует по Кинопоиску и цифрового релиза не
требует: у большинства российских фильмов TMDB его просто не записывает.

Поэтому за русским кино ходи в `kino ru`, а не фильтруй общую выдачу по стране —
там его почти не будет. В русской дорожке поле `notice` предупреждает, что часть
фильмов пока только в прокате; это стоит передать пользователю.

## Пустой ответ

`films: []` — нормальный ответ, а не сбой: за неделю может не выйти ничего
достойного. Предложи более широкое окно (`kino 30`, `kino 90`), но не выдумывай
фильмы и не подставляй их из своих знаний — пользователь ждёт ответа про то, что
реально вышло и доступно.

## Чего не делать

**Не запускай `kino sync`, `kino update`, `kino refresh` и `kino setup`.** Это
сетевые операции: они тратят суточные квоты (Кинопоиск — 200 запросов) и уже
выполняются по расписанию. Если данные кажутся устаревшими — скажи об этом
человеку, решение за ним.

Если данные выглядят устаревшими, посмотри `tail -3
~/.local/share/kino/sync.log` — там время последнего обновления и код возврата.
Расскажи человеку, что увидел, и предложи настроить крон:
`(crontab -l 2>/dev/null; echo "0 6 * * * $HOME/.local/bin/kino-daily") | crontab -`.
Запускать обновление самостоятельно всё равно не нужно.

**Не советуй фильмы из своей памяти рядом с выдачей.** Смысл инструмента в том,
что рекомендация опирается на измеренные оценки и проверяемую доступность.
Смешивать их с припомненным — значит потерять единственное, ради чего он есть.
