# Подключение к агентам

`kino` — обычная CLI-программа. Любому агенту, умеющему выполнять команды
оболочки, хватает трёх вещей: бинарь в `PATH`, наполненная база и абзац в
системном промпте о том, когда её звать и как читать ответ.

## Предварительно

```bash
go build -o ~/.local/bin/kino ./cmd/kino
kino setup          # ключи и первое наполнение базы; запускает человек
kino config check   # ключи видны, база не пуста, квоты на месте
```

Мастер `kino setup` спрашивает ключи API и требует терминал. Агенту его
запускать нельзя, и в промптах ниже это сказано прямо.

## Универсальный блок для системного промпта

Работает в любом рантайме, который умеет запускать команды. Скопировать целиком:

```text
У тебя есть CLI-инструмент kino — рекомендатор фильмов поверх локальной базы
IMDb, TMDB и Кинопоиска. Он отвечает без сети и мгновенно.

Зови его, когда просят посоветовать фильм, спрашивают про новинки и свежие
релизы, хотят кино определённого жанра за период или спрашивают отдельно про
русское кино.

Команды (всегда с --format json, разбирай JSON, а не текст):
  kino --format json              три фильма, вышедших в цифре за 7 дней
  kino 30 --format json           окно 30 дней
  kino ru 180 --format json       русскоязычное за полгода
  kino комедия 60 --format json   жанр за 60 дней
  kino 90 --all --format json     все прошедшие отбор, не только тройка
  kino watched "Название" 8       отметить просмотренным
Число — дни, ru — дорожка русскоязычного кино, слово — жанр, порядок любой.

Как читать ответ:
- "rating": null означает «никто не голосовал», а не ноль. Не говори, что
  фильм плохо приняли, если оценки просто нет.
- availability.online_ru: null означает «не проверяли». Это не то же самое,
  что false. Не утверждай, что фильм недоступен.
- why.points объясняют оценку: четыре слагаемых минус три штрафа. Если
  спрашивают «почему этот фильм» — отвечай ими.
- Не пересортировывай выдачу: score уже учитывает объём выборки, массовость и
  свежесть. Сортировка по сырому рейтингу IMDb поднимет фильмы с десятком
  голосов.
- films: [] — нормальный ответ. За неделю может не выйти ничего достойного.
  Предложи окно шире, но не подставляй фильмы из своих знаний.

За русским кино ходи в kino ru, а не фильтруй общую выдачу по стране: общая
дорожка требует подтверждённого цифрового релиза, которого у большинства
российских фильмов в TMDB нет.

Не запускай kino sync, update, refresh и setup. Это сетевые операции, они
тратят суточные квоты и уже выполняются по расписанию.
```

## Claude Code

Скилл ставится копированием — глобально или в проект:

```bash
mkdir -p ~/.claude/skills
cp -r skills/kino ~/.claude/skills/
```

```bash
mkdir -p .claude/skills && cp -r /путь/к/kino-cli/skills/kino .claude/skills/
```

После этого `SKILL.md` подхватывается по описанию: агент сам решает позвать
`kino`, когда разговор заходит о том, что посмотреть. Вручную — `/kino`.

Проверка: спросить «посоветуй что-нибудь свежее» и убедиться, что в ходе ответа
выполнился `kino --format json`.

## Codex

Codex читает `AGENTS.md` из корня рабочего каталога. Добавить туда раздел:

```markdown
## Рекомендации фильмов

Для вопросов «что посмотреть» используй CLI `kino` с флагом `--format json`.
Контракт ответа и правила чтения — в docs/AGENTS.md этого репозитория.
Коротко: null в рейтинге значит «нет голосов», null в online_ru значит «не
проверяли», выдачу не пересортировывать, kino sync/update/refresh не запускать.
```

Если `kino` нужен в проекте, который сам к нему отношения не имеет, положи туда
копию `docs/AGENTS.md` — иначе ссылка будет вести в никуда.

## Hermes

Каталог скиллов, проверено на живой установке 2026-09-02:

```bash
mkdir -p ~/.hermes/skills/media/kino
cp skills/kino/SKILL.md ~/.hermes/skills/media/kino/SKILL.md
```

Промежуточный уровень (`media`) — категория; она произвольна, но структура
`~/.hermes/skills/<категория>/<имя>/SKILL.md` соблюдается.

После этого агент сам зовёт `kino --format json`, когда разговор заходит о том,
что посмотреть.

## OpenClaw и прочие рантаймы

**Формат конфигурации OpenClaw я не проверяла**, а угаданный путь к файлу хуже
отсутствующего. Работает подход, не зависящий от рантайма:

1. Вставить универсальный блок выше в системный промпт агента — тем способом,
   каким этот рантайм вообще задаёт системный промпт.
2. Убедиться, что у агента есть право выполнять команды оболочки, и что
   `~/.local/bin` попадает в его `PATH` (у демонов и сервисов он часто урезан —
   ровно поэтому обёртка крона `kino-daily` задаёт `PATH` явно).
3. Проверить руками: `kino 30 --format json` из той же среды, в которой живёт
   агент.

## Если рядом живёт другой инструмент с именем kino

Проверь, не занят ли путь к базе:

```bash
grep -rl 'share/kino' ~ --include='*.py' --include='*.toml' --include='*.yaml' 2>/dev/null
```

На реальной установке нашёлся Python-проект, чей конфиг по умолчанию указывал на
тот же `~/.local/share/kino/kino.db`. Два инструмента, пишущих в один файл
SQLite, рано или поздно испортят его друг другу. Развести можно, не трогая
чужой проект:

```toml
# ~/.config/kino/config.toml
[general]
db_path = "~/.local/share/kino-cli/kino.db"
```

или переменной `KINO_DB`, или флагом `--db` в каждом вызове. Первый способ
надёжнее: он действует и на крон, и на агента.

## Проверка подключения

```bash
kino 30 --format json | head -20
```

Ожидается объект с полями `track`, `window_from`, `window_to` и массивом `films`.
Ошибка вместо JSON — читай текст: он называет причину (нет ключа TMDB, пустая
база, неизвестный жанр).

Отдать агенту наружу — например через SSH на сервер — можно так:

```bash
ssh kino-host 'kino ru 90 --format json'
```

Инструменту не нужны ни состояние сессии, ни рабочий каталог: он читает базу и
конфиг по абсолютным путям.
