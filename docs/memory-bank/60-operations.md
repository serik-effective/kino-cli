# Эксплуатация

## Ежедневное обновление

```bash
kino sync
```

Пять шагов, каждый переживает падение остальных — упавший шаг печатает ошибку,
прогон продолжается, а код возврата в конце говорит, сколько шагов не удалось.
Для крона это принципиально: недельная порция рейтингов не должна теряться
из-за часового простоя одного сервиса.

| шаг | что делает | чем платим |
|---|---|---|
| 1 | датасеты IMDb, если копии больше `--imdb-after` дней (7) | ~50 c, 111 МБ |
| 2 | мировые цифровые релизы за `--window` (7d) | TMDB, безлимит |
| 3 | русскоязычные релизы за `--ru-window` (1m), любой тип релиза | TMDB, безлимит |
| 4 | срез каталога КП за `--kp-years` (2) | 4 запроса из 200/сутки |
| 5 | рейтинги КП | бесплатно, без квоты |

Тренды с торрент-трекера вынесены под `--with-trends` и по умолчанию выключены:
к рекомендациям отношения не имеют, а роняют прогон, когда трекер недоступен.

## Крон

Установлено:

```
0 6 * * * /Users/sbeysenov/.local/bin/kino-daily
```

`kino-daily` — обёртка: задаёт PATH (cron даёт голый), пишет в
`~/.local/share/kino/sync.log` с отметкой времени и кодом возврата, подрезает
лог до 2000 строк.

Посмотреть, как отработало:

```bash
tail -30 ~/.local/share/kino/sync.log
```

## Что НЕ обновляется само

Ничего. С появлением `update kp` российское кино — id, рейтинги, доступность —
приезжает автоматически.

Браузерное расширение (`extension/`) остаётся только для произвольных подборок,
которые пользователь листает сам. Как основной механизм оно отменено: каталог
КП отдаёт то же самое дешевле и полнее.

## Квоты

| источник | лимит | на что тратим |
|---|---|---|
| TMDB | нет | discovery и детали, кэш 24 ч |
| poiskkino | 200/сутки | `update kp`: 4 запроса при пороге 3000 голосов, 17 при пороге 10; бюджет ограничен `--max-pages` (40) |
| OMDb | 1000/сутки | опциональное обогащение, в `sync` не входит |
| rating.kinopoisk.ru | нет | `refresh ratings` |
| Wikidata | — | **недоступна с этой сети**, `refresh kp-ids` не работает |
| IMDb datasets | нет | еженедельно |

Проверить: `kino config check`.

## Ручные операции

```bash
kino watched <название> [оценка]   # отметить просмотренным
kino watched --list
kino watched --forget <название>

kino config init                   # создать config.toml с текущей моделью
kino config show                   # какие коэффициенты действуют

kino import kp <файл.json>         # выгрузка расширения или плеера
```

## Пересборка

```bash
go build -o ~/.local/bin/kino ./cmd/kino
```

Бинарь ставится в `~/.local/bin` — он уже в PATH и не требует sudo.
ВАЖНО: после правок обязательно переустанавливать, иначе пользователь работает
со старой сборкой. В этой сессии так потерялся почти день изменений.

## Новая установка

```bash
kino setup
```

Опрос → ключи → `update imdb` + `sync`. Наполнение запускает настоящие команды
через свежее дерево cobra, а не копию их логики: первый прогон и ежедневный
обязаны быть одним и тем же кодом.

Отказывается работать, если ввод не терминал (в скриптах — `kino config init`),
и не перезаписывает существующий `config.toml` без `--force`.

При переносе на сервер `setup` не нужен: достаточно скопировать `config.toml`
(права 0600) и базу.

## Перенос базы на другую машину

Только снимком, не копированием файла:

```bash
sqlite3 ~/.local/share/kino/kino.db "VACUUM INTO '/tmp/kino-snapshot.db'"
```

База в режиме WAL. Простое `cp` даст состояние без последних транзакций, а если
в этот момент сработает крон — разорванный снимок.

При замене базы на месте **удаляйте `-wal` и `-shm` вместе с ней**: журнал от
старой базы будет применён к новой при открытии, и это прямой путь к
повреждению.

Датасеты IMDb (1.94 млн строк из 2.09 млн, 139 МБ из 161) можно не везти:
`kino update imdb` восстановит их за ~50 секунд бесплатно. Снимок без них —
6.9 МБ в gzip против 47 МБ целиком.

Ловушка первого запуска: `kino` создаёт пустую базу при любом обращении, включая
`config check`. После этого `install.sh` видит существующий файл и отказывается
его перезаписывать — защита от затирания более свежей серверной базы срабатывает
против переноса. Проверять `SELECT count(*) FROM movies` после установки.


## Первичное наполнение пустой базы

Порядок важен: бесплатное и объёмное раньше квотируемого. ~30 минут.

```bash
kino update imdb                                    # 1.7 млн оценок, ~50 с
kino update movies --last 1y --min-votes 50         # TMDB, без лимита
kino update movies --last 1y --original-language ru --release-type any
kino update kp --from-year 2024 --min-votes 10 --add-missing   # ~17 запросов
kino refresh ratings --limit 2000                   # бесплатно
```

Квоту тратит только четвёртая строка. Она идемпотентна: прервалась — повторить.

## Совместное проживание с чужим kino

На сервере Hermes нашёлся Python-проект `~/workspace/kino`, чей конфиг по
умолчанию указывает на тот же `~/.local/share/kino/kino.db`. Два процесса,
пишущих в один файл SQLite, испортят его друг другу.

Развести, не трогая чужой проект:

```toml
# ~/.config/kino/config.toml
[general]
db_path = "~/.local/share/kino-cli/kino.db"
```

Тильда раскрывается (с 2026-09-02; до этого путь брался буквально и SQLite
создавал каталог с именем `~` в рабочем каталоге — база тихо появлялась в
нескольких местах). Работают также `KINO_DB` и `--db`, но конфиг надёжнее:
действует и на крон, и на агента.
