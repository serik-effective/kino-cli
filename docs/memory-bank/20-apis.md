# API: факты и грабли (ресерч 2026-08-27)

## TMDB — основной источник открытия (discovery)
- Base `https://api.themoviedb.org/3`. Auth: `Authorization: Bearer <v4_token>` (предпочтительно) либо `?api_key=<v3>`.
- `GET /discover/movie` — главный эндпоинт фичи №1.
  - `with_release_type`: 1=Premiere, 2=Theatrical(limited), 3=Theatrical, **4=Digital**, 5=Physical, 6=TV. Запятая=AND, пайп=OR (`4|6`).
  - Окно дат: `release_date.gte` / `release_date.lte` (YYYY-MM-DD). `primary_release_date.*` — только основная дата, для цифровых не годится.
  - `region` (ISO-3166-1, напр. US/RU) — обязателен вместе с `with_release_type`, иначе матч по любой стране и мусор.
  - Фильтры: `vote_average.gte/lte`, `vote_count.gte/lte`, `with_original_language`, `sort_by` (popularity|vote_average|primary_release_date|vote_count|revenue|title ×asc/desc), `page` (1..500, по 20).
- **Грабля**: discover фильтрует приблизительно. Точную цифровую дату брать из `GET /movie/{id}/release_dates` (массив по странам, `type:4`) и перепроверять окно перед записью в БД.
- Фильтры по происхождению: `with_original_language` (ISO 639-1, напр. `ru` — ловит и казахстанское кино, снятое на русском) и `with_origin_country` (ISO 3166-1, напр. `KZ`). Язык оригинала и страна производства — разные вещи: у казахстанского «Becoming» язык `kk`, страны `FR NL LT KZ SE`.
- **Грабля**: `release_date.*` работает только вместе с `with_release_type`+`region`. Без типа релиза окно надо задавать через `primary_release_date.*`, иначе TMDB матчит даты любой страны и выдаёт мусор.
- Экономия запросов: `GET /movie/{id}?append_to_response=release_dates,external_ids` — 1 запрос вместо 3, даёт `imdb_id`.
- Лимиты: жёсткого дневного нет; мягкий потолок ~40–50 req/s, легаси 40/10s отключён в 2019. Уважать 429 + backoff.
- Изображения: отдаются как `poster_path`, полный URL строится через `/configuration` (кэшировать сутки).

## OMDb — обогащение рейтингами
- Base `https://www.omdbapi.com/?apikey=<key>`. Ключ бесплатный, **1000 запросов/сутки**.
- Только по одному тайтлу за запрос: `i=tt1285016` (imdbID — самый надёжный), `t=`, `s=` (поиск, page 1..100), `plot=short|full`, `y=`, `type=movie`.
- Даёт: `imdbRating`, `imdbVotes`, `Metascore`, `Ratings[]` (в т.ч. Rotten Tomatoes), `BoxOffice`, `Rated`, `Awards`, `Runtime`, `Director/Actors`.
- **Грабля**: ошибки приходят HTTP 200 с `{"Response":"False","Error":"..."}`. Числа — строки («N/A», «1,234,567»), парсить руками.

## Кинопоиск — через poiskkino.dev (проверено вживую 2026-08-27)
- Бот `@kinopoiskdev_bot` теперь выдаёт токен для **poiskkino.dev**, не для kinopoisk.dev. Base `https://api.poiskkino.dev`, header `X-API-KEY`. Форк с той же схемой фильтров.
- **Версии**: весь `/v1.4/*` помечен deprecated. Использовать **`/v1.5/*`**.
- **Пагинация в v1.5 курсорная**: в ответе `next`/`prev`/`hasNext`/`hasPrev`; следующую страницу тянуть параметром `next=<курсор>`, листать пока `hasNext`. Никаких `page`. `withCount=true` даёт total, но сильно замедляет — не включать.
- OpenAPI-схема машиночитаемо: `https://api.poiskkino.dev/documentation-json` (единственный надёжный источник, сайт документации — SPA и через WebFetch не читается).
- **`GET /v1.5/token`** — `requestsLimit/requestsUsed/requestsRemaining/resetAt`, **сам лимит не тратит**. Проверено: free = **200/сутки**, сброс в 21:00 UTC.
- `GET /v1.5/movie` — универсальный фильтр. `limit`, `selectFields` (повторяемый параметр), `notNullFields`, `sortField`+`sortType` (1|-1).
  - Синтаксис: диапазон `rating.kp=7.2-10`, `year=2020-2024`, `votes.kp=1000-6666666`; исключение `genres.name=!криминал`; обязательное включение `+драма`.
  - Даты — формат **DD.MM.YYYY**, диапазон `01.01.2020-31.12.2020`.
  - **`premiere.digital`** — прямой фильтр по дате цифровой премьеры. Плюс `premiere.russia/world/usa/cinema`.
  - Матчинг: `externalId.imdb=tt0232500`, `externalId.tmdb=9799`.
  - Ещё полезное: `rating.imdb`, `rating.tmdb`, `votes.*`, `lists` (напр. `top250`), `watchability.items.name` (ivi/okko/...), `genres.slug`, справочники `/v1.5/dictionary/{type}`.
- Даёт: `rating.kp/imdb/tmdb/filmCritics`, `votes.*`, `name` (RU) / `alternativeName`, `description`, `poster`, `watchability` (где смотреть в РФ), `premiere.*`.
- **Грабля**: выдача `premiere.digital` замусорена короткими роликами КП («О чём на самом деле …»), у них бывает kp-рейтинг и тысячи голосов. Фильтровать `type=movie` + порог `votes.kp` + отсутствие `externalId.imdb` как сигнал мусора.
- **Грабля**: поля часто null, схема плавает между версиями — читать defensive.

## rating.kinopoisk.ru — бесплатные рейтинги (проверено 2026-08-27)
- `GET https://rating.kinopoisk.ru/<kp_id>.xml` — **без ключа, без квоты**. Отдаёт `kp_rating` и (не всегда) `imdb_rating`, у обоих атрибут `num_vote`.
```xml
<rating><kp_rating num_vote="2588665">8.686</kp_rating><imdb_rating num_vote="454000">7.8</imdb_rating></rating>
```
- Кодировка **Windows-1251** в декларации → xml.Decoder без `CharsetReader` упадёт. Payload числовой, но декодируем честно через `charmap.Windows1251`.
- Неизвестный id → **404 с HTML**, не XML. У фильмов без оценок значения бывают `null` / `-1`.
- Точнее poiskkino: KP отдаёт 5.311 там, где API округляет до 5.4. Обновляется чаще.
- Троттлинга при 12 запросах подряд не видно, заголовков лимита нет, `expires` +5 мин. Эндпоинт недокументированный (Яндекс) → держим 2 rps и считаем сбои мягкими.
- **Ключевой вывод**: poiskkino нужен ровно один раз — чтобы получить `kp_id` по `externalId.imdb`. Дальше рейтинги обновляются бесплатно и без лимита. Квота 200/сут тратится только на новые фильмы.

## Wikidata — бесплатный резолв kp_id (проверено 2026-08-27)
- `GET https://query.wikidata.org/sparql?query=<SPARQL>`, заголовок `Accept: application/sparql-results+json`. **Без ключа, без дневной квоты.**
- Связка: `wdt:P345` (IMDb ID) → `wdt:P2603` (Kinopoisk ID).
```sparql
SELECT ?imdb ?kp WHERE { VALUES ?imdb { "tt0232500" "tt1285016" } ?f wdt:P345 ?imdb; wdt:P2603 ?kp . }
```
- Пачками по **250 id** в `VALUES` — укладывается в лимиты URL и таймаута. Держим 1 запрос/сек, требуется осмысленный `User-Agent` (WDQS банит дефолтные).
- **Реальный выхлоп**: 1324 imdb-id → 401 kp_id за **6.4 секунды, 6 запросов**. Платный poiskkino за весь дневной лимит 200 дал 22.
- Не знает в основном свежие релизы (2026-й) — их добирает poiskkino, плюс имеет смысл повторять команду через месяцы: Викиданные дозаполняются.
- **Это снимает узкое место КП**: квота нужна только на резолв id, а Викиданные закрывают треть бесплатно; дальше рейтинг идёт с `rating.kinopoisk.ru` без лимита.

## Покрытие рейтингов: чего ждать
- Проверено 2026-08-27 на 117 русскоязычных релизах за месяц: **рейтингов нет практически нигде**. У TMDB 1–5 голосов, OMDb/КП по `externalId.imdb` не находят (у 45 из 122 фильмов вообще нет imdb_id), у poiskkino по `premiere.russia` за тот же месяц `rating.kp = null`.
- Причина не в источниках: фильму младше месяца рейтинг ещё неоткуда взять. Рейтинги подтягиваются позже — для этого и нужен дешёвый `refresh ratings` по расписанию.
- TMDB по `with_original_language=ru` выдаёт много короткого метра и фестивального — это реальные записи базы, не мусор парсинга.

## Трекеры как сигнал популярности (разведка 2026-08-27)
Собираем **только метаданные** — названия, ранги, сиды, счётчики скачиваний. Никаких торрентов и контента.

| Источник | Статус | Почему |
|---|---|---|
| rutor.info/.org | **недоступен** | режет провайдер, редирект на `lawfilter.ertelecom.ru` |
| rutracker.org | **недоступен** | `tracker.php` за Cloudflare-челленджем («Just a moment…»), плюс требует логин. Обход бот-защиты не делаем |
| **kinozal.me** | **работает** | без логина, robots.txt явно `Allow: /browse.php`, `/top.php`, `/details.php?id=` |

### kinozal.me
- Кодировка страниц **Windows-1251**.
- `GET /top.php?t=0&d=0&f=0&c=0&k=0&j=&s=0&w=N` — чарт: `w=1` неделя, `w=2` месяц, `w=6` полгода, без `w` — за всё время. **50 позиций, порядок = ранг.** Отдаёт сетку постеров: `<a href='/details.php?id=NNN' title='...'>`.
- **Грабля**: параметр `c` (категория) на `top.php` игнорируется — чарт всегда смешанный (сериалы, музыка, книги, игры). Фильтровать названия на клиенте; из 50 позиций фильмами оказываются ~12–15.
- `GET /browse.php?c=1002&t=1[&page=N]` — категория «фильмы», `t=1` сортировка по популярности. Строки `<tr class=bg>`, колонки по порядку: комментарии, размер, **сиды** (`sl_s`), **личи** (`sl_p`). Прочие `t`: 0 дата, 3 размер, 4 комментарии. `w` на browse — это свежесть раздачи (1 сегодня, 2 вчера, 3 три дня), **не** окно тренда.
- `GET /details.php?id=N` — «Раздают N Скачивают N **Скачали N** Комментариев N». Счётчик скачиваний виден без логина. Один запрос на релиз.
- Формат названия: `RU / Original / Год / метки / качество`, оригинальное название может отсутствовать. HTML-entities (`&#039;`) надо раскодировать.
- Держим **1 rps**.

### Как из этого получается тренд
`Скачали` — накопительный счётчик, не «за период». Поэтому пишем снапшоты и считаем **дельту между снапшотами**: первый прогон даёт только абсолют, со второго появляется скорость. Если снапшота старше отсечки нет, база берётся самая ранняя в окне — честнее, чем ноль.

## Выгрузка плеера Кинопоиска (discovery_player)
JSON, который отдаёт плеер КП на странице фильма. Не API — снимается вручную из браузера, ключа и квоты не требует.
- Структура: объект, ключи вида `"<filmId>,, 0, rnd-0.82…"`, значения — `{film{…}, views, streamUrl, videoContentId}`. Несколько ответов часто склеены подряд — парсер читает поток JSON-объектов.
- Полезное: `film.id` = **kp_id**, `title`/`originalTitle`, `year` (бывает `"с 2026"` у сериалов), `type` MOVIE|SHOW, `country.name`, `genres`, `kinopoiskRating.value/count`, `views`, `onlineViewOption.isAvailableOnline/text` (подписка или цена).
- **Безопасность**: `streamUrl` — подписанные ссылки, привязанные к сессии (`ottsessionid`, `ysign1`). Не парсим, не храним, не используем.
- **Зачем**: единственный найденный бесплатный источник `kp_id` для российских фильмов — Викиданные их не знают. Плюс закрывает «где смотреть в РФ», чего не было ни в одном источнике.
- Команда: `kino import kp <file.json>`. Матчинг: сначала по `kp_id`, потом по нормализованному названию (RU/EN/оригинальное) с годом ±1. Сериалы отсекаются, если не указан `--all-types`.

## Стратегия квот
TMDB — дешёвый, им и открываем. OMDb/KP — дорогие по квоте, только для обогащения уже отобранных фильмов, батчами с дневным лимитом и кэшем (не перезапрашивать, если `enriched_at` свежее N дней).

## poiskkino: каталог, а не только резолвер id

`GET /v1.4/movie` с фильтрами — главное открытие 2026-08-28.

Параметры: `year=2025-2026` (диапазон строго 1874–2050, иначе HTTP 400),
`votes.kp=3000-99999999`, `countries.name`, `type=movie`, `sortField=votes.kp`,
`sortType=-1`, `page`, `limit` (до **250**), `selectFields` (повторяемый).

Отдаёт: `id` (kp_id), `name`, `enName`, `year`, `rating.{kp,imdb}`,
`votes.{kp,imdb}`, `externalId.{imdb,tmdb}`, `premiere.digital`,
**`watchability.items[]`** со списком сервисов и ссылками.

ВАЖНО про стоимость: одна страница — 250 фильмов за ОДИН запрос из квоты 200/сутки.
Весь российский каталог за 2 года (820 фильмов) обошёлся в 4 запроса.
Прежняя оценка «923 фильма = две недели по 200/день» была ошибкой: она исходила
из того, как клиент использовал API (один фильм на запрос через `ByIMDb`), а не
из того, что API умеет.

`externalId.imdb` есть далеко не у всех — у среза 2026 года лишь у 38 из 182,
поэтому основной путь сопоставления остаётся «название + год ±1».

### Потолок демо-тарифа: страница 10

`/v1.4/movie` отдаёт `pages: 17`, но одиннадцатая страница возвращает HTTP 403:
«На демо-тарифе доступны только страницы с 1 по 10». Потолок — 2500 фильмов на
запрос, сколько бы их ни было в срезе.

Обход — не страницы, а **полосы по голосам**. Выдача отсортирована по `votes.kp`
убыванию, поэтому после десятой страницы достаточно опустить верхнюю границу
`votes.kp` до наименьшего увиденного значения и начать заново. Реализовано в
`pipeline.UpdateKP` + `nextCeiling`.

Ловушка, ради которой у `nextCeiling` есть тест: если у всех фильмов полосы
одинаковое число голосов, наименьшее увиденное равно запрошенному потолку, и
цикл вечно тянет одну и ту же страницу. Шаг вниз на единицу безопасен — фильм с
ровно таким числом голосов уже учтён.

Оттуда же бюджет `--max-pages` (по умолчанию 40): в патологическом случае
лестница спускается по одному голосу за шаг и без бюджета выест суточную квоту.

### Wikidata недоступна

`query.wikidata.org` и `www.wikidata.org` не отвечают с этой сети — таймаут на
уровне соединения, как у rutor. `kino refresh kp-ids` работать не может.
Практически это не потеря: Wikidata отдаёт только `kp_id`, за которым всё равно
нужен отдельный запрос за рейтингом, тогда как каталог приносит id, рейтинг,
голоса и сервисы разом, по 250 фильмов за запрос.
