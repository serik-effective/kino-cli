# Решения (ADR-лог, одна строка = одно решение)

- 2026-08-27 Go 1.26 + cobra — стандарт для CLI, дешёвые подкоманды.
- 2026-08-27 SQLite (modernc, pure-Go) вместо JSON/BoltDB — нужны фильтры по рейтингу/датам и джойны; билд без cgo.
- 2026-08-27 TMDB = источник открытия, OMDb/KP = только обогащение — у TMDB нет дневной квоты, у остальных 1000/200.
- 2026-08-27 Ключ маппинга между источниками — `imdb_id` (tt…), а не название.
- 2026-08-27 Цифровую дату верифицируем через `/movie/{id}/release_dates`, discover-у не доверяем.
- 2026-08-27 Секреты только в env / `~/.config/kino/config.yaml` (chmod 600), в репо — `.env.example`.
- 2026-08-27 Регион по умолчанию US — у TMDB полнота digital-дат по US кратно выше.
- 2026-08-27 `--min-rating` по умолчанию бьёт по TMDB-рейтингу — доступен на этапе discover, фильтрует до трат квоты.
- 2026-08-27 RU-тексты берём из TMDB `language=ru-RU`, не из КП — бесплатно, без расхода 200/сут.
- 2026-08-27 Интерфейс для агентов v1 — `--format json` в stdout; MCP-сервер отложен.
- 2026-08-27 Кинопоиск = poiskkino.dev `/v1.5` (не kinopoisk.dev, не v1.4) — бот выдаёт токен туда, v1.4 deprecated.
- 2026-08-27 Квоту КП читаем из `/v1.5/token` (бесплатно), локальный счётчик — только для OMDb.
- 2026-08-27 poiskkino остаётся источником обогащения, не открытия: `premiere.digital` замусорен роликами КП; TMDB для discovery чище.
- 2026-08-27 Рейтинги КП/IMDb обновляем через `rating.kinopoisk.ru/<kp_id>.xml` — без ключа и квоты, значения точнее, чем у API (5.311 против 5.4).
- 2026-08-27 poiskkino-квота тратится только на резолв `kp_id`; если `kp_id` уже в БД, `enrich` идёт по бесплатному XML.
- 2026-08-27 XML не перетирает `imdb_rating`, пришедший из OMDb (OMDb авторитетнее), только заполняет пустое. Флаг `--overwrite-imdb` для обратного.
- 2026-08-27 Отдельная колонка `ratings_at` (миграция 002) — свежесть рейтингов отслеживается независимо от `enriched_at`.
- 2026-08-27 `update digital` обобщён в `update movies` (алиас `digital` сохранён) с флагом `--release-type digital|theatrical|...|any`.
- 2026-08-27 При `--release-type any` окно задаётся по `primary_release_date`, регион игнорируется, дата матча = основная дата релиза (колонка `movies.release_date`, миграция 003).
- 2026-08-27 Страны производства хранятся в `movies.countries` (JSON ISO-кодов, миграция 004) — язык оригинала не отвечает на вопрос «казахстанский ли фильм».
- 2026-08-27 Фильтры `--original-language` и `--origin-country` есть и в `update` (TMDB-запрос), и в `list` (локально).
- 2026-08-27 Трекер-источник — только kinozal.me: rutor режет провайдер, rutracker за Cloudflare (бот-защиту не обходим).
- 2026-08-27 Собираем исключительно метаданные (названия/ранги/сиды/скачивания); торренты и контент не трогаем.
- 2026-08-27 Тренд = дельта накопительного счётчика «Скачали» между снапшотами, а не абсолют. Таблицы `torrents` + `torrent_stats` (миграция 005).
- 2026-08-27 Несколько рипов одного фильма (1080p/4K/разные озвучки) схлопываются в одну строку тренда по `tmdb_id` через GROUP BY.
- 2026-08-27 Матчинг релиз→TMDB только при точном совпадении нормализованного названия и года ±1; иначе `match_state='unmatched'`, без догадок.
- 2026-08-27 Ярлыки — встроенные подкоманды cobra, не шелл-алиасы: работают в любом шелле, видны в `--help`, наследуют все флаги базовой команды.
- 2026-08-27 Фабрики `newListCmdWith`/`newTrendsListCmdWith` принимают структуру дефолтов — пресет не дублирует ни логику, ни флаги.
- 2026-08-27 Бинарь ставим в `~/.local/bin` (уже в PATH, без sudo), не в /usr/local/bin.
- 2026-08-27 Массовая заливка идёт срезами с порогом `--min-votes 10` для US: без порога TMDB отдаёт 6942 записи за год, из них ~85% короткий метр с нулём голосов, который ломает сортировки.
- 2026-08-27 `kp_id` резолвим сначала через Wikidata (P345→P2603, бесплатно, ~30% попаданий за секунды), и только остаток — через квоту poiskkino.
- 2026-08-27 `SetKPIDs` не перезаписывает уже занятый другим фильмом `kp_id` — защита от кривого маппинга.
- 2026-08-27 Скриншоты как источник данных отклонены: не масштабируются на тысячи фильмов, а OCR-ошибки в рейтингах неотличимы от настоящих значений.
- 2026-08-27 Выгрузки плеера КП импортируем командой `import kp`: даёт kp_id для российских фильмов (которых нет в Викиданных) и доступность в РФ.
- 2026-08-27 `streamUrl` из выгрузки игнорируем полностью — подписанные персональные ссылки, хранить их нельзя.
- 2026-08-27 `ApplyKPInfo` только проставляет `kp_id`, никогда не меняет существующий: кривой матч по названию не должен перепривязать фильм.
- 2026-08-27 Допуск фильма к рейтингу — многоисточниковый: `imdb_votes>=300 OR tmdb_votes>=100 OR kp_votes>=3000`. Порог §6 ТЗ меряет надёжность выборки, а не вкус; у русского кино массовая аудитория живёт на КП. По одному лишь порогу ТЗ за год проходили 8 русских фильмов из 1753, с допуском по КП — 115.
- 2026-08-27 Кинопоиск разрешён в трёх ролях: допуск по объёму выборки, справочная строка в карточке, ранжирование внутри `kino ru`. Запрещён в `kino_score` общей выдачи и в виде редакционных подборок.
- 2026-08-27 `kino ru` — отдельная дорожка ранжирования по КП с байесовским сглаживанием, а не общий алгоритм: при `v≈0` байес по IMDb схлопывается к глобальному среднему, и русский фильм не попал бы в TOP-3 никогда. Источник ранжирования пишем в шапке вывода.
- 2026-08-27 IMDb datasets: `title.ratings` грузим целиком (~1,5 млн строк), `title.basics` — gzip-потоком с фильтром `titleType='movie' AND isAdult=0 AND startYear>=imdb_year_floor`, полностью не храним (11+ млн строк, ~900 МБ).
- 2026-08-27 Конфиг переехал на `~/.config/kino/config.toml` (зависимость BurntSushi/toml). Приоритет снизу вверх: встроенные дефолты → config.toml → устаревший config.env → реальные переменные окружения. `config.env` читается только ради ключей, коэффициентов в нём никогда не было.
- 2026-08-27 Частичный config.toml переопределяет только упомянутые ключи: декодер получает структуру, уже заполненную дефолтами, а не нули.
- 2026-08-27 `Tuning.Validate()` валит загрузку, если веса не дают в сумме 1.0 — иначе кривой конфиг молча перекосил бы всю выдачу.
- 2026-08-27 Источник рейтинга с нулём голосов выбрасывается из формулы, а не сглаживается к среднему: иначе фильму, которого никто не оценил на TMDB, приписывался бы выдуманный 6.5 с весом 0.25. Освободившийся вес переходит оставшемуся источнику.
- 2026-08-27 Сигналы 0..1 (confidence, mainstream, freshness) домножаются на 10 перед сложением с рейтингами: иначе их веса ничего не значат рядом с 7.5.
- 2026-08-27 Жанр в arthouse учитывается только вместе с низкой аудиторией (`genre *= lowAudience`): документалка с миллионом оценок не артхаус. Drama весит 0.2 — минимум из ниш-жанров, потому что большинство массовых фильмов это драмы.
- 2026-08-27 «Вышел в цифре» = САМАЯ РАННЯЯ дата type=4 по фильму (§4 ТЗ). По любой дате в окне в топ лезли переиздания: «Бойцовский клуб» с US-релизом 2026-05-12 при первом цифровом 2011-09-08. В 30-дневном окне таких строк 181.
- 2026-08-27 Для `kino ru` цифровым релизом считается появление фильма в плеере КП (`watch_seen_at`, миграция 008). Причина: у русского кино, которое люди смотрят, в TMDB нет релизов type=4 — из 81 фильма с `watch_online=1` у 48 нет ни одной такой строки. Дата ставится один раз («первый раз увидели») и переимпортом не двигается.
- 2026-08-27 Старый листинг-пресет `kino ru` переименован в `kino ru-list`: имя `ru` заняла ранжирующая дорожка из ТЗ. Листинг остаётся доступен и как `kino list --original-language ru`.
- 2026-08-27 Жанровые ярлыки матчатся по нескольким написаниям (`{"триллер","Thriller"}`): каталог хранит жанры на языке из конфига, по умолчанию русском.
- 2026-08-27 Таблица `scores` из §17 ТЗ не заводится: freshness зависит от окна запроса, поэтому оценка считается на лету, а не кэшируется. Кэш дал бы устаревшие числа при смене периода.
- 2026-08-27 Ключ `api_cache` — SHA-256 от URL, а не сам URL: у OMDb ключ API лежит в query-строке, и таблица кэша не должна становиться хранилищем секретов.
- 2026-08-27 Откат на устаревший кэш работает при сетевой ошибке и 5xx, но НЕ при 4xx: 401 из-за неверного ключа или 404 — это настоящий ответ, и подменять его старыми данными значит прятать проблему.
- 2026-08-27 TTL кэша TMDB — 24 часа. Выдача discover меняется медленно, суточной свежести достаточно, а экономия на повторных прогонах — 70x (5.2 с против 0.075 с, ноль сетевых вызовов).
- 2026-08-28 Браузерное расширение `extension/` — не скраппер по построению: в манифесте нет сетевых разрешений, только `storage` и content-script на kinopoisk.ru. Читает уже отрисованный DOM вкладки, которую открыл человек; не листает выдачу и не открывает карточки.
- 2026-08-28 Опора парсинга — ссылка `/film/<id>/`, а не CSS-классы: у Кинопоиска классы обфусцированы и меняются. Год и рейтинг ищутся регулярками в тексте карточки и считаются best-effort; `kp_id` собирается всегда.
- 2026-08-28 Расширение отдаёт ровно тот JSON, который понимает `kino import kp` — новой команды на стороне Go не заводим.
- 2026-08-28 Рейтинг без числа голосов не перетирает рейтинг, за которым голоса стоят (`ApplyKPInfo`, CASE по `kp_votes`): число, снятое регуляркой с карточки, менее надёжно, а ошибка чтения была бы неотличима от настоящего изменения.
- 2026-08-28 `ratings_at` обновляется только когда импорт реально принёс голоса. Импорт из расширения несёт один `kp_id`, и раньше он помечал фильм «свежим»: бесплатный `refresh ratings` пропускал такие записи навсегда. Тот же класс ошибки, что и с перетиранием рейтинга без голосов — запись утверждала больше, чем знала.
- 2026-08-28 Тип фильм/сериал определяется по тексту карточки («(сериал)», «(мини-сериал)»), а не по URL: Кинопоиск отдаёт сериалы по адресам `/film/`. По href находилось 15 сериалов из 434, остальные 417 ушли бы в импорт как фильмы и матчились через TMDB-поиск фильмов.
- 2026-08-28 Фильтр по рейтингу в расширении выключен по умолчанию: рейтинг виден на 64 карточках из 788, и гейт по нему выбрасывал 94% сбора. Качество отсеивает `kino` после `refresh ratings`.
- 2026-08-28 `onlineViewOption` в парсере — указатель, а не структура: отсутствие ключа («источник не знает») отличается от пустого объекта («не доступен»). `DiscoveryItem.OnlineKnown` несёт это различие до `ApplyKPInfo`, который трогает `watch_online` только когда источник действительно про него говорил. Расширение ключ не шлёт вовсе.
- 2026-08-28 Freshness в русской дорожке считается по настоящей дате релиза фильма (`movies.release_date`), а не по `watch_seen_at`: последняя — дата нашего импорта, и все фильмы одной выгрузки получали бы одинаковую фору, а следующая выгрузка топила бы предыдущую партию без всякой связи с фильмами. Если настоящей даты нет — сигнал не выдаётся (0), а не угадывается.
- 2026-08-28 `confidence_ceiling` поднят со 100 000 до 500 000: на нашей базе в старый потолок упирались и 73K голосов IMDb, и 202K на КП — сигнал перестал различать. ТЗ задаёт «100 000+ = очень высоко», но это не про наши данные.
- 2026-08-28 Бейдж «международная аудитория оценила заметно ниже» требует минимальной выборки с ОБЕИХ сторон (`gap_min_votes = 100`): 2.9 от 49 человек против 8.3 от 156 тысяч — это не расхождение аудиторий, а шум с одной стороны.
- 2026-08-28 В русской дорожке снято требование `watch_online = 1`, окно считается по `release_date`. Гейт по доступности превращал выдачу в отчёт об одном снимке плеера: «Роднина» с 8.28 на 335 тысячах голосов была невидима только потому, что не попала в выгрузку. Цена решения: из 62 кандидатов 18 доступны лишь в прокате, поэтому шапка честно предупреждает.
- 2026-08-28 Шапка русской дорожки — «новые русскоязычные фильмы», не «российские»: фильтр стоит по `orig_lang='ru'`, и в выдаче законно присутствуют казахстанские (42) и белорусские (15) фильмы.
- 2026-08-28 Текст предложения КП («С мультиподпиской Яндекс Плюс») заменён на «Есть на Кинопоиске»: тарифы меняются, факт доступности — нет.
- 2026-08-28 Штраф за разрыв КП/IMDb действует только в русской дорожке и только когда КП выше: обратное о фильме ничего плохого не говорит. Нужна выборка ≥100 голосов с обеих сторон, иначе 2.9 от 49 человек штрафовали бы фильм за неизвестность за рубежом.
- 2026-08-28 Каталог КП (`GET /v1.4/movie` с фильтрами) — основной источник российского кино вместо ручного расширения: одна страница отдаёт 250 фильмов за один запрос, весь срез за 2 года стоит 4 запроса из 200/сутки. Расширение остаётся только для произвольных подборок.
- 2026-08-28 `watchability` из каталога пишется в `watch_services` списком, а не булевом: разница между «идёт где-то» и «идёт там, где у меня подписка». Каталог всегда возвращает это поле, поэтому его молчание честно означает «нигде» — здесь `OnlineKnown` ставится в true законно.
- 2026-08-28 Матчинг в `UpdateKP` идёт по убыванию надёжности: `kp_id` → `imdb_id` → название с годом ±1. Шаг по `imdb_id` новый; раньше эта связка, единственная не требующая угадывания, в сопоставлении не использовалась.
- 2026-08-28 Шаги `kino sync` не фатальны: упавший печатает ошибку, остальные идут дальше, код возврата сообщает число неудач. Ежедневный крон не должен терять всю работу из-за часового простоя одного источника.
- 2026-08-28 `kino setup` — опрос из пяти вопросов вместо чтения config.toml на первом запуске. Отображение «ответ -> коэффициенты» живёт в `internal/config/interview.go`, а не в cli: чистую функцию можно прогнать по всем 216 комбинациям ответов и проверить, что каждая проходит `Validate()`. Нейтральные ответы обязаны давать ровно `DefaultTuning()` — мастер не имеет права молча перенастроить того, кто ничего не выбирал.
- 2026-08-28 Веса после опроса квантуются до сотых с остатком на самый крупный член. Шаблон печатает `%.2f`, поэтому ненормированные веса записались бы округлёнными и при чтении дали бы сумму 0.99 — мастер выдавал бы файл, который сам же отвергает.
- 2026-08-28 Проверка терминала — `isatty`, а не `Stat().Mode()&ModeCharDevice`: `/dev/null` тоже символьное устройство, и под `go test` и под cron наивная проверка объявляет его терминалом, после чего опрос «отвечает» сам себе тишиной.
- 2026-08-28 Каталог КП обходится по полосам голосов, а не по страницам: демо-тариф отдаёт максимум 10 страниц (2500 фильмов) и отвечает 403 на одиннадцатую. Опускание верхней границы `votes.kp` до последнего увиденного фильма продолжает обход ровно с места остановки.
- 2026-08-28 У `update kp` появился бюджет запросов (`--max-pages`, по умолчанию 40), и `sync` его передаёт: лестница по полосам в вырожденном случае спускается по одному голосу за шаг, а крон не имеет права выесть суточную квоту.
- 2026-09-02 У рекомендатора появился `--format json`: до этого флаг молча игнорировался, и карточки были единственным выводом. Ответ несёт окно и дорожку, а не только список фильмов — список без вопроса, на который он отвечает, интерпретировать нельзя.
- 2026-09-02 Рейтинги в JSON — указатели: источник без голосов даёт `null`, а не 0.0. То же для `availability.online_ru`, где `null` значит «не проверяли». Это та же граница «источник, который чего-то не знает, не отвечает на этот вопрос», из-за которой раньше терялись данные при импорте расширения.
- 2026-09-02 Вклад каждого слагаемого в оценку сохраняется в `Breakdown` (поля `*Points`), а не пересчитывается снаружи по весам: объяснение, считающее себя само, рано или поздно разойдётся с арифметикой, которую объясняет.
- 2026-09-02 Жанры распознаются и по-русски: раньше карта алиасов имела только английские ключи, хотя каталог хранит русские названия и README обещал оба языка. `kino комедия` падал с ошибкой.
- 2026-09-02 `kino config init` пишет туда же, откуда читает `Load`: раньше он игнорировал `KINO_CONFIG` и всегда бил в `~/.config/kino/config.toml`. Флага `--path` при этом не существовало, хотя переменная под него в коде была. В этой сессии баг создал config.toml в живой установке, которую никто не просил трогать.
