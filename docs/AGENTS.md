# kino для агентов

Здесь — контракт: команды, формат ответа, правила чтения. Разбор того, что уже
пошло не так на живой установке, — в [AGENT-PLAYBOOK.md](AGENT-PLAYBOOK.md);
прочитай его, если ставишь, переносишь или обновляешь kino.

Машинный интерфейс к локальной базе фильмов. Сеть не нужна: всё, что отвечает на
запрос, лежит в SQLite. Обновление данных — отдельная операция, которую делает
крон, а не запрос.

## Один вопрос — одна команда

```bash
kino --format json                 # 3 фильма, вышедших в цифре за 7 дней
kino 30 --format json              # окно 30 дней
kino ru 180 --format json          # русскоязычное за полгода
kino комедия 60 --format json      # только комедии
kino 90 --all --format json        # все прошедшие отбор, не только TOP-3
kino 90 --reissues --format json   # вместе с переизданиями старых фильмов
```

Позиционная грамматика: `ru` переключает дорожку, число — окно в днях, слово —
жанр. Порядок свободный.

Жанры понимаются по-русски и по-английски: `драма`/`drama`, `комедия`/`comedy`,
`триллер`/`thriller`, `ужасы`/`horror`, `фантастика`/`sci-fi`,
`детектив`/`mystery`, `боевик`/`action`, `криминал`/`crime`,
`мелодрама`/`romance`, `мультфильм`/`animation`,
`документальный`/`documentary`, `семейный`/`family`,
`приключения`/`adventure`, `фэнтези`/`fantasy`, `история`/`history`,
`музыка`/`music`, `военный`/`war`, `вестерн`/`western`.

## Правила чтения — важное

**`null` в рейтинге означает «никто не голосовал», а не «ноль».** Фильм без
оценок на Кинопоиске вернёт `"rating": null`. Прочитать это как 0.0 и сказать
пользователю, что зрителям фильм не понравился, — самая вероятная ошибка при
работе с этим форматом.

**`availability.online_ru` трёхзначно.** `true` — доступен, `false` — проверяли
и нет, **`null` — не проверяли**. Говорить «недоступен» при `null` нельзя.
`theatrical_only: true` ставится только тогда, когда доступность действительно
проверена и фильм идёт в прокате, но не дома.

**`points` складываются в `score`.** Четыре слагаемых минус три штрафа дают
итоговую оценку — с точностью до округления до сотых и ограничения в 0..10
(фильм, у которого штрафы уводят сумму ниже нуля, получает 0). Это единственный
способ объяснить пользователю, почему фильм в списке.

**`smoothed_ratings` складывать нельзя.** Это сглаженные рейтинги на шкале
0..10, ингредиенты, а не вклады.

**`rating_sources` говорит, на чём фильм оценён.** В общей дорожке Кинопоиск в
ранжировании не участвует, даже когда его рейтинг показан в `ratings`.

**`films` — всегда массив**, пустой при отсутствии результатов, никогда `null`.

**Переиздания отсеиваются.** Старый фильм, доехавший до нового стримингового
сервиса, — не новинка: «Клео от 5 до 7» 1962 года, появившаяся в цифре в декабре,
в выдачу не попадёт. Порог — разрыв больше двух лет между годом производства и
датой цифрового релиза. Если человек прямо просит переиздания, ремастеры или
«что из классики появилось онлайн», добавь `--reissues`.

## Две дорожки

|  | `general` | `russian` |
|---|---|---|
| источники оценки | IMDb + TMDB | Кинопоиск, IMDb/TMDB как контроль |
| `release_date` | подтверждённый цифровой релиз | дата релиза; фильм может быть ещё в прокате |
| порог допуска | 300 голосов IMDb или 100 TMDB | 3000 голосов Кинопоиска |

Дорожки разделены потому, что TMDB для большинства российских и казахстанских
фильмов не содержит записи о цифровом релизе. Требовать её значило бы
вычеркнуть это кино целиком.

В русской дорожке `notice` предупреждает, что ранжирование идёт по Кинопоиску, а
часть фильмов пока только в прокате. Это стоит передавать пользователю.

## Просмотренное

```bash
kino watched "Коммерсант" 8      # отметить, оценка необязательна
kino watched --list
kino watched --forget "Коммерсант"
```

Отмеченные фильмы исчезают из рекомендаций. Вернуть: флаг `--seen`.

## Произвольные запросы

Когда вопрос не «что посмотреть», а «найди фильмы с такими-то свойствами»:

```bash
kino list --since 1m --original-language ru --release-type any --format json
kino list --since 30d --rating-source imdb --min-rating 7 --format json
kino show tt1285016 --format json
```

`list` отдаёт сырые строки базы без ранжирования и без объяснений.

## Чего делать не нужно

**Не запускать `kino sync`, `update` и `refresh` без явной просьбы.** Это
сетевые операции, они тратят суточные квоты (Кинопоиск — 200 запросов) и уже
выполняются по расписанию. Рекомендации читаются из локальной базы и свежести от
них не требуют.

**Не выдумывать фильмы, которых нет в ответе.** Пустой список — валидный ответ:
за неделю может не выйти ничего, что проходит порог. В этом случае честнее
предложить более широкое окно.

**Не ранжировать заново.** `score` уже учитывает объём выборки, массовость,
свежесть и штрафы. Сортировка по сырому `ratings.imdb.rating` вернёт фильмы с
десятком голосов.

## Наполнение и обновление базы

Всё в этом разделе — **сетевые операции с суточной квотой**. Выполняй их только
по явной просьбе человека. Сам, по своей инициативе, не запускай ничего отсюда:
пустой список фильмов не повод обновлять базу, это повод предложить окно шире.

### Проверить состояние

```bash
kino config check                          # база, ключи, остаток квот
tail -3 ~/.local/share/kino/sync.log       # когда обновлялось в последний раз
crontab -l | grep kino                     # настроено ли расписание
```

Три ответа, которые из этого складываются:

| что видишь | что это значит |
|---|---|
| `rows in movies` = 0 | база пустая, нужно первичное наполнение |
| `sync.log` старше суток или его нет | обновление не идёт |
| в `crontab` нет `kino-daily` | расписание не настроено |

Сообщи человеку, что нашёл, и предложи действие ниже. Не выполняй его молча.

### Первичное наполнение пустой базы

Порядок важен: сначала бесплатное и объёмное, потом квотируемое. Целиком
занимает около получаса.

```bash
kino update imdb                                    # 1.7 млн оценок, ~50 с, без ключа и квоты
kino update movies --last 1y --min-votes 50         # мировые релизы за год, TMDB без лимита
kino update movies --last 1y --original-language ru --release-type any
kino update kp --from-year 2024 --min-votes 10 --add-missing   # ~17 запросов из 200
kino refresh ratings --limit 2000                   # рейтинги Кинопоиска, бесплатно
```

Квоту тратит только четвёртая строка. Если она прервалась — повтори её позже,
она идемпотентна; остальные повторять не нужно.

**Порядок не переставляется, и первый шаг сам по себе бесполезен.** Датасет
IMDb — словарь рейтингов, а не список вышедшего: он только проставляет оценки
фильмам, которые уже есть, и на пустой базе создаёт ноль фильмов. Фильмы заводит
TMDB (`update movies`), он же приносит даты цифровых релизов, по которым
ранжирует общая дорожка. Если после `update imdb` в базе пусто — это не сбой,
это ещё не сделанный второй шаг.

Гораздо дешевле, если у человека уже есть наполненная база на другой машине:
перенести её снимком (см. README, раздел про перенос) — это минуты вместо
получаса и ноль запросов.

### Настроить ежедневное обновление

```bash
install -m 755 ~/incoming/kino/kino-daily ~/.local/bin/kino-daily
(crontab -l 2>/dev/null | grep -v kino-daily; \
 echo "0 6 * * * $HOME/.local/bin/kino-daily") | crontab -
crontab -l
```

`grep -v kino-daily` в середине не украшение: без него повторный запуск добавит
вторую строку, и обновление будет ходить в сеть дважды.

Проверить, что расписание отработает, можно один раз вручную:

```bash
kino-daily; tail -12 ~/.local/share/kino/sync.log
```

Ожидается `exit=0`. Один прогон — около двадцати запросов из двухсот суточных,
поэтому **ровно один раз**, не в цикле и не «для надёжности».

### Забрать весь каталог за несколько дней

Каталог Кинопоиска больше суточной квоты: 1990–2026 — около 183 000 фильмов,
~730 запросов при 200 в сутки. Одним прогоном не берётся, но берётся за
несколько дней:

```bash
install -m 755 ~/incoming/kino/scripts/kino-backfill ~/.local/bin/kino-backfill
(crontab -l 2>/dev/null | grep -v kino-backfill; \
 echo "30 7 * * * $HOME/.local/bin/kino-backfill") | crontab -
```

**Время обязано отличаться от `kino-daily`**, иначе они подерутся за квоту.
Скрипт оставляет 40 запросов дневному обновлению и не выходит в сеть, если
остатка не хватает; где остановился — помнит в
`~/.local/share/kino/backfill.state`, по завершении сам перестаёт тратить квоту.

Это предложение человеку, а не то, что запускают молча: добор идёт несколько
дней и всё это время держит квоту занятой.

### Обновление рейтингов

Отдельно настраивать нечего: `kino sync` перечитывает рейтинги сам, а период
зависит от возраста фильма — до 30 дней раз в сутки, до 90 дней втрое реже, до
года в четырнадцать раз, дальше в шестьдесят. Оценка свежего фильма движется
быстро, оценка старого практически стоит.

Поэтому «рейтинг устарел» почти никогда не бывает причиной что-то запускать
руками.

### Если база в общем каталоге с другим инструментом

Проверь, не пишет ли кто-то ещё в тот же файл:

```bash
grep -rl 'share/kino' ~ --include='*.py' --include='*.toml' --include='*.yaml' 2>/dev/null
```

Два процесса, пишущих в один файл SQLite, испортят его друг другу. Развести
можно, не трогая чужой проект: `db_path` в `~/.config/kino/config.toml`,
переменная `KINO_DB` или флаг `--db`. Первое надёжнее — действует и на крон.

## Коды возврата

`0` — успех, `1` — ошибка (текст в stderr, stdout пуст). Нет ключа TMDB, пустая
база и недоступный источник — всё это ошибки с внятным текстом.

Проверить состояние: `kino config check` (ключи, размер базы, остаток квот).
